## Capture and file sources

The MAIN reader is self-contained because `scripting.executeScript` serializes its function. It receives only job/chat/organization identifiers and bounded action arguments. It has no extension runtime access. Background accepts privileged relay requests only from the registered extension runner tab.

The conversation GET is `/api/organizations/{org}/chat_conversations/{chat}` with the page-observed tree/message-rendering query. The primary fields are `chat_messages`, `current_leaf_message_uuid`, message UUIDs, `parent_message_uuid`, ordered `content` blocks, `files`, and `attachments`. Message-level `text` can be empty while `content[].text` contains the transcript. Follow the current leaf's ancestry; response array order/global indices can include hidden alternative branches.

Generated files appear in `tool_result.content` as `local_resource` descriptors with `file_path`, `name` and `mime_type`. Retrieve them through `/api/organizations/{org}/conversations/{chat}/wiggle/download-file?path={encodedPath}`; strip a leading `computer://`. Original text/image/document uploads use their `file_uuid`/`uuid` through `/api/organizations/{org}/files/{uuid}/contents`. **Blob uploads** (including CSV, PPTX, BIN, ZIP and XPI) instead use their response-provided `/mnt/user-data/uploads/...` path through the conversation download-file route: their UUID contents endpoint returns 404 even for newly uploaded originals. Live XPI bytes established this distinction. Preserve UUID identity for deduplication and the response path for retrieval. Legacy `attachments` use `id` and `file_size`; live validation confirmed the contents endpoint for those records. Claude's loaded public client confirms both download helpers and permits conversation upload paths. Display routes such as `/preview`, `/thumbnail`, and `/document_pdf` are separate and do not prove original-byte recovery.

Claude-hidden thinking can have `truncated: true` while the visible answer is complete. Exclude that hidden block from completeness errors; visible content truncation, unfinished text and the page's streaming indicator still count. Live validation caught this distinction in completed conversations.

In the Sonnet 5.5 Medium synthetic suite, generated PNG/JPEG downloads acquired server-added C2PA provenance metadata. Their generator-side hashes differed, while comparison against the originals inside Claude's bundle confirmed identical non-provenance image payloads. Preserve downloaded provenance bytes; validate transport against the delivered resource and distinguish service transformations from exporter corruption. Other tested suite files matched the generator manifest byte-for-byte.

All file reads use the source session in MAIN. Validate HTTP outcome, attachment disposition, byte counts and chunk offsets. Retry transient failures and unexpected partial/short responses within a fixed attempt limit. Authentication failures become explicit file failures; avoid logging headers or response bodies. Preserve filenames from Content-Disposition safely, including Unicode, while preventing archive traversal and collisions.

Repeated generated paths identify currently available server contents, not independently recoverable historical versions. Retain each message reference and record this limitation. Different full paths with the same basename remain distinct.

## Completeness and lifecycle

The fallback uses `[data-testid="transcript-row"]`, `data-index`, `data-perf-row`, article `aria-posinset`/`aria-setsize`, and `[data-autoscroll-container="true"]`. Traverse overlapping windows, settle rendering, refresh already-seen rows and restore the original scroll. Indexed contiguous coverage is required for a complete fallback result. Preserve code whitespace and table structure. Unsupported attachment cards remain visible failures rather than disappearing from counts.

Job state is stored separately from transcript/file bytes. An inactive extension tab owns progress, staging and final ZIP construction; closing the popup does not cancel it. Transcript chunks are at most 65,536 UTF-16 code units; binary chunks contain at most 256 KiB raw bytes encoded independently for Chromium's JSON messaging. The next offset acknowledges the previous chunk after staging commits. Temporary export storage is unencrypted and separate from the credential vault. A new export prunes abandoned chunks from earlier jobs after a browser crash.

Automatic cookie-changing refreshes defer during export. Explicit account changes cancel the export before changing cookies. MAIN leases expire abandoned state. Completion, cancellation and failure release readers, temporary storage and Blob URLs; the final ZIP URL lives until download settlement.

Starting another request cancels any partially consumed response stream first, including capacity-rejected files and optional summary excerpts. Empty stream chunks are valid and skipped. Summary capture checks source consistency again before returning content for the existing opt-in Gemini action.

Every archive includes `transcript.md` and `export-report.json`, with optional `attachments/`. Build local links after file outcomes are final. Missing content/files produce an `_INCOMPLETE` archive and warning. Excluding attachments intentionally is a skipped outcome. Explicit Cancel saves no archive. Normal manual and unrelated downloads remain native; no global download cancellation or filename cooldown is used.

The builder uses classic ZIP limits (65,535 entries and under 4 GiB total). Reserve entries and byte space for the transcript/report before adding attachments. Reject oversized attachments before transferring known lengths, and check capacity during unknown-length streams so recovered text and failure details can still be saved.

## Validation workflow

1. Run syntax checks and `node --test tests/export-data.test.mjs tests/export-reader.test.mjs tests/export-jobs.test.mjs tests/regressions.test.mjs`. Run `tests/export-dom.cjs` for fallback changes.
2. Build with `python package.py`, then run `node tests/export-installed.cjs` with `PLAYWRIGHT_MODULE` and `CHROMIUM_BINARY` configured. Alternatively pass the existing Playwright module directory and browser executable as the first two arguments. The fixture uses a new profile and mocked websites, and writes private results to `temp/export-installed-results.json`. It needs browser permission to write its synthetic download directory; Windows restricted execution produced `FILE_ACCESS_DENIED`, while an approved unrestricted run passed. Exercise original/downloaded bytes, missing files, retries, unrelated downloads, popup closure/reopen, cancellation, source/account changes and storage cleanup.
3. Validate the nine maintainer-provided chats in personal Brave: HTML/JS/CSS, Markdown, tables/code, ZIP/XPI, PDF/PPTX, batch/shell scripts, user images and user PDF.
4. Use Sonnet 5.5 Medium in dedicated synthetic Claude chats for long-text and generated/uploaded sample-file checks. Preserve known input bytes for comparison. Unsupported uploads are recorded, not disguised. Synthetic fixture success does not replace this step.
5. Run `node tests/export-firefox.mjs` for the Firefox runner and Chrome/Firefox installed backup/package smoke checks. Firefox uses WebDriver BiDi network interception ([protocol specification](https://www.w3.org/TR/webdriver-bidi/#command-network-provideResponse)) with synthetic responses and a fresh profile. Update this status with the actual outcomes before preparing a release.

Reload existing Claude tabs after updating from an older HotSwap build: old page-world download hooks remain in already-running pages until navigation/reload. The replacement observer intentionally installs no new download hooks.
